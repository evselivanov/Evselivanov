# Виртуальная команда для разработки криптоарбитражной системы

Состав ролей и их распределение по агентам. Конфиги субагентов Claude Code лежат в `.claude/agents/` — каждая роль вызывается из основной сессии как отдельный агент со своим системным промптом.

## Роли и агенты

| Роль | Агент | Модель | Зачем эта роль |
|---|---|---|---|
| Архитектор / тимлид | основная сессия Claude Code | Opus | декомпозиция задач, дизайн системы, координация остальных |
| Маркет-дата | `market-data-engineer` | Sonnet | стримы ордербуков, нормализация, контроль качества данных |
| Стратегии | `strategy-developer` | Opus | расчёт спредов, поиск возможностей, размер позиций |
| Исполнение | `execution-engineer` | Opus | отправка ордеров, идемпотентность, расползание ног |
| Риск-контроль | `risk-engineer` | Sonnet | лимиты, kill-switch, сверка балансов |
| Бэктест | `backtester` | Sonnet | проверка стратегий на истории, стресс-тесты чувствительности |
| Ончейн / DEX | `onchain-engineer` | Opus | контракты атомарного исполнения, флешлоаны, защита от MEV |
| DevOps | `devops-engineer` | Sonnet | деплой, CI/CD, мониторинг, логирование |
| Пост-трейд аналитика | `post-trade-analyst` | Haiku | разбор фактических сделок, сверка PnL с ожиданиями |
| Ревью кода | `code-reviewer` | Opus | независимое ревью, только чтение |

Логика распределения моделей: Opus — там, где ошибка стоит денег (исполнение, стратегии, ончейн, ревью); Sonnet — объёмная инженерная рутина; Haiku — дешёвая массовая аналитика.

## Ключевые принципы

- Пары «данные → сигнал → исполнение → риск» разделены по агентам: у них разные требования (полнота / корректность расчёта / надёжность / консервативность).
- Ревьюер не совмещается с автором кода — нужен независимый взгляд.
- Риск-модуль имеет право заблокировать любую сделку; fail-closed везде.
- Ни одна стратегия не идёт в лайв без бэктеста; ни одна транзакция — без симуляции.

## Бесплатная альтернатива

Тот же состав ролей можно закрыть бесплатными инструментами — меняются только исполнители:

**Оболочки:** Cline / Roo Code (open-source расширения VS Code), Aider (open-source CLI), Gemini CLI (бесплатный лимит Google), Qwen Code (бесплатный лимит Alibaba), OpenHands.

**Модели:** DeepSeek V3/R1, Qwen3-Coder, Gemini 2.5 (free tier), либо локально через Ollama (Qwen2.5-Coder 32B и т.п. — нужна GPU с 16–24+ ГБ).

| Роль | Бесплатный вариант |
|---|---|
| Архитектор, стратегии, исполнение, ончейн | DeepSeek R1/V3 или Gemini 2.5 Pro (free tier) |
| Маркет-дата, риск, бэктест | Qwen3-Coder через Qwen Code |
| DevOps, пост-трейд | Gemini Flash |
| Ревью кода | всегда другая модель, чем писала код |

Оговорки для бесплатного стека:

1. **Приватность.** Бесплатные API обычно вправе обучаться на ваших данных — код стратегий (ваш эдж) туда отправлять рискованно. Локальный Ollama снимает проблему.
2. **Лимиты.** Free-тарифы режут частоту запросов — для разработки терпимо. В самом торговом цикле LLM не нужны вовсе: бот — детерминированный код.
3. **Компромисс.** Критичные модули писать/ревьюить сильной моделью, рутину отдать бесплатным.

## Юридическая оговорка

Арбитраж легален, но перед запуском стоит проверить правила конкретных бирж (ограничения на HFT-паттерны) и налоговые последствия сделок в своей юрисдикции.
